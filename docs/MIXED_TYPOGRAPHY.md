# 中英文混排处理（2026-09-18）

## 诊断与取舍

当前 Web 编辑器曾对中文正文强制使用 `text-justify: inter-word`，标题使用 `word-break: keep-all`，同时在分页完成后执行 Han.js `render()`。前两者倾向于英文／按空格分词的断行方式；后者改变已测量文本的字距、标点及 DOM。主题还优先使用 DejaVu／FreeSans 等西文字体，中文依赖未明确指定的系统回退。它们组合起来会造成英文周围大空隙、中文标题不自然换行，以及分页前后不一致。

## 实现

- 按用户对同文样张的反馈，正文、列表、引用恢复两端对齐，使用 `text-justify: auto`，末行左对齐。普通英文保持完整；裸网址单独允许字符间换行，避免它将上一行撑出大空隙。这仍不是具有字距上下限的完整印刷均排算法。
- 混排正文中的英文／数字采用 0.94em 视觉字号、正常字距和原基线，继承所在段落的行高和加粗。纯英文段落、标题、代码、链接和原文不变；字体不同仍可能需要用户微调。
- 中文与西文都采用 `word-break: normal`、严格标点禁则；英文优先完整换行，无法容纳的超长内容才应急折行。不默认套用英文自动连字符。
- 原生 `text-autospace: normal` 处理汉字与字母／数字之间的视觉间距，不修改正文字符串。已有空格不自动清理；加粗、斜体等行内边界由浏览器处理。
- 旧浏览器在分页前用同一兼容转换补细空格，识别跨 strong/em/span 的边界；保护代码、链接、注音与含 URL 的文本，保留作者已有空白。此兼容模式的细空格宽度随字体变化，不等同于原生精确度。
- 富文本复制与公众号路径使用普通空格兼容第三方编辑器；Markdown 不受影响。公众号自身字体与过滤规则仍由平台决定。
- 删除 Web／打印入口的 Han CSS/JS CDN 依赖。标点不再一律施加负半字距，仅在浏览器支持时使用上下文 `text-spacing-trim`；不支持时保留标准全角标点。
- 主题使用明确的中文黑体／宋体回退；保留用户字体选择。Google Fonts 请求改为 Noto Serif SC。字体离线可回退，但本轮不保证各系统字体完全同宽，也没有实现完整的字体／图片加载屏障。
- 预览使用分页前处理，打印同样采用原生规则且不在 Paged.js 分页后再改文字。尚未完成真实打印机、Firefox/WebKit 和微信公众号保存回读验收。

## 专业资料

查阅日期：2026-09-18。下列规范部分仍是草案，作为实现依据而非“全面合规”声明。

- [W3C 中文排版需求 CLReq](https://www.w3.org/TR/clreq/)：第 6 章，断行禁则、中西文均排及字距调整。中文不能简单按英文词距排齐；字距扩展应有边界。
- [CSS Text 3：text-justify](https://www.w3.org/TR/css-text-3/#text-justify-property)：`inter-word` 只扩展词分隔符；`auto` 可按语言和书写系统选择算法。
- [CSS Text 4：text-autospace](https://www.w3.org/TR/css-text-4/#text-autospace-property)：原生视觉间距不改变文本内容，normal 包含汉字／字母和汉字／数字间距，草案当前定义为 1/8 汉字宽；不是向原文插入空格。
- [Han.js 官方 API](https://hanzi.pro/manual/js-api)：`render()` 不仅加空格，还依次处理强调、悬挂、标点挤压和替换；不适合在已经确定页高后无条件再执行。

## 回归

`tests/mixed-typography.test.ts` 覆盖跨行内标签、组合附加符号、扩展汉字、数字、全角字母、原样保护、重复处理、原生／兼容路径及复制。

`tests/fixtures/mixed-typography.html` 提供 345px／560px 实际浏览器阅读样张。主编辑器仍保留用户原文，不会载入测试内容覆盖草稿。

`tests/fixtures/justified-typography.html` 使用用户截图的相同段落，对照左对齐与修复后的齐行排版；自动测量非末行右侧空白、标点禁则与英文名称完整性。本机样张最大右侧空白从 97.29px 降为 0.02px，无横向溢出，SemiAnalysis 保持完整；这不是跨字体、跨浏览器的通用数值保证。
